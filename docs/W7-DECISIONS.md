## 一、固件行为（W6b 包更新线，7 项）

### 1. check_updates 全量重下（#33）
- **背景**：现在每次更新检查，manifest 里所有包不管本地是不是最新，全部重新下载覆盖。注释自己写的"简化"。包多了浪费流量和 TF 寿命。
- **选项**：A) 按包名读本地 .msp 版本号，不一致才下（标准做法）；B) 保持全量重下（最省事，反正包小）。
- **推荐 A**。改动不大，我把版本比对逻辑加上就行。

### 2. TLS 跳过主机名校验（#34）
- **背景**：json_fetcher 把 HTTPS 证书主机名校验关了（只验证书链）。好处是 GitHub raw 那种 SAN 不全的地址也能连；坏处是中间人能劫持包更新线注入假包（OTA 固件线不受影响，只影响商店/脚本包）。
- **选项**：A) 恢复严格校验，镜像源换到证书规范的地址；B) 保持跳过，接受风险（自己玩的小机器，风险可控）；C) 白名单：只对配置的 mirror 域名跳过，其他严格。
- **推荐 B**（个人项目、本地镜像为主），等哪天要公开分发再收紧。选 B 的话这条直接关，不用改代码。

### 3. 自动更新窗口写死凌晨 2-5 点（#37）
- **背景**：update_scheduler 判断 `t.hour < 6` 才更新。你在界面上设 23 点 = 永远不触发。
- **选项**：A) 窗口改成用你配置的值；B) 删掉窗口判断，到点就更新；C) 保持现状，界面只允许设 0-5 点。
- **推荐 A**。一行改动。

### 4. 到点不自动连 WiFi（#38）
- **背景**：注释说"到点自动连"，实际没连——没 WiFi 就跳过，而且当天标了"已触发"不再重试。晚上自动更新基本永远失败。
- **选项**：A) 到点主动连 WiFi（有保存凭据时），失败再放弃当天；B) 保持现状（反正手动更新能用）。
- **推荐 A**。

### 5. manifest 缺 crc 字段（#41）
- **背景**：manifest 条目没有 crc 字段时 crc=0，包下载后 CRC 对不上全部拒装——一个字段缺失整个包装不上。
- **选项**：A) 缺 crc 就跳过校验直接装（信任镜像源）；B) 缺 crc 视为清单错误跳过该包；C) 保持现状（强制要求 manifest 带 crc）。
- **推荐 A**（个人镜像源可信，少一道折腾）。

### 6. manifest 字段顺序敏感（#42）
- **背景**：解析器要求 name 必须出现在 version 前面，顺序反了后面字段解析不全。
- **选项**：A) 改成按字段名独立扫描（顺序无关）；B) 保持现状，约定 manifest 固定格式。
- **推荐 A**。顺手的事，解析器本来就小。

### 7. json_find 解析限制（#44）
- **背景**：changelog 里带转义引号会被截断；固件清单 URL 拼接依赖 mirror 是"目录型"地址，换 TF 卡路径源时不适用。
- **选项**：A) 记个限制不改（反正 changelog 没人写转义引号）；B) 换用现成 JSON 解析库。
- **推荐 A**。为这俩边角功能引个库不值。
