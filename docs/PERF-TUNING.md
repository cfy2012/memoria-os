# Memoria OS · 硬件潜力压榨清单（PERF-TUNING）

> 目标：把 ESP32-S3 N16R8（双核 240MHz + 8MB PSRAM + 16MB Flash）的性能全部用起来，
> 让系统配得上这批料。本文是路线图，按性价比排序，每项标注工作量/风险/状态。
> 定版日：2026-10-06（由豆包-2 起草，报桥后按窗口排期）

## 0. 现状基线（boot log 实录，2026-10-02 固件）

| 项 | 实测值 | 备注 |
|----|--------|------|
| CPU 频率 | **160 MHz** | `cpu freq: 160000000 Hz`，双核但未充分利用 |
| 内部 RAM 可用 | ~146 KiB + 21 KiB + 32 KiB DRAM + 7 KiB RTC | 3FCC4D10 / 3FCE9710 / 3FCF0000 / 600FE000 |
| PSRAM | 8 MB（8192K，已入堆分配器） | 80MHz Octal |

## P0 · 白捡档（改配置，无新代码，无风险）

### P0-1 CPU 频率 160 → 240 MHz
- **现状**：160MHz，浪费 1/3 主频。
- **改法**：sdkconfig 设 `CONFIG_ESP_DEFAULT_CPU_FREQ_MHZ_240`。
- **收益**：全系统算力 +50%，解码/渲染/输入法全部受益。
- **风险**：电流略升，注意 BOD（配合背光错峰，见 §3 备注）。
- **状态**：✅ 已完成（2026-10-06，bin 5D086356 / v1.2.1）。当时回退系 boot 期射频电流误账（E47B83D9 实锤），boot 零射频架构落地后 240 重开，BOD SEL_7 全程在线，用户真机反复上电验收稳定。

### P0-2 关键模块编译优化
- **现状**：默认优化档。
- **改法**：对 `memoria_drivers`（解码）/`memoria_gfx`（渲染）单独 -O3 或开 LTO。
- **收益**：热循环 10~30%。
- **风险**：低；-O3 增大固件体积，注意 3MB factory 分区余量。
- **状态**：☐ 待窗口

## P1 · 双核真分工（写代码，中工程量，收益最大）

### P1-1 任务 pinning（xTaskCreatePinnedToCore）
- **现状**：重活与 UI 混跑，core 1 空转。
- **目标分工**：
  - **core 0**：MP3/AAC 解码、MJPG 视频解码、录音编码、WiFi/BLE 协议栈
  - **core 1**：UI 渲染、键盘扫描、输入法、shell、模式调度
- **改法**：解码/渲染相关 task 显式 pin；关键 task 提优先级。
- **收益**：解码与 UI 并行，卡顿大头直接消失。

### P1-2 音视频双缓冲流水线
- **现状**：串行"解一帧→显一帧"。
- **目标**：core 0 解帧 N+1 写双缓冲，core 1 显示帧 N → 帧率翻倍，解码时间被显示时间掩盖。
- **收益**：视频帧率接近翻倍；音乐解码零卡顿。
- **状态**：☐ 待窗口

## P2 · 内存分层（让 8MB PSRAM 干该干的活）

原则：**冷数据大块放 PSRAM，热数据小块留内部 RAM**。

| 数据 | 放哪 | 依据 |
|------|------|------|
| framebuffer（300KB）、字库、音频环形缓冲 | PSRAM | 大、低频访问 |
| ISR、键盘扫描、解码热循环、DMA 描述符 | 内部 RAM / IRAM_ATTR | 高频、怕延迟 |
| 常驻全局小变量 | 内部 RAM | 每次访问省 PSRAM 延迟 |

- **改法**：盘一遍 `memoria_gfx`/`memoria_kernel` 里高频路径是否误用 PSRAM 大块；热循环函数加 `IRAM_ATTR`。
- **风险**：IRAM 总量有限（S3 内部 IRAM ~512KB，但可用段有限），加多了编不过，需挑热点。
- **状态**：☐ 待窗口

## P3 · 外设频率试探（有 BOD 风险，需实测）

### P3-1 SPI LCD 80 → 120 MHz
- **改法**：`LCD_SPI_FREQ_HZ` 试 120MHz，花屏/雪花就退 100/80。
- **收益**：全屏刷新 31ms → ~20ms（≈50fps 上限）。
- **风险**：**拉频率=拉电流**，与 GLM BOD 课题直接相关——必须保持背光 init 半亮错峰，brownout 阈值不动（SEL_1）。
- **状态**：☐ 待窗口（真机实测项）

## P4 · SIMD（终极形态，后期做）

- **能力**：ESP32-S3 128-bit SIMD（PIE 指令集），帧拷贝/RGB565 填充/字库渲染/解码数学循环可向量化。
- **参考**：ESP-DL 库即基于此跑 AI；手写汇编或 intrinsics。
- **收益**：密集循环 2~4×。
- **成本**：工程量最大、可维护性差，最后做。
- **状态**：☐ 远期

## 执行顺序建议

1. **P0-1 CPU 240MHz**（一行配置）→ 立即可见
2. **P1-1 双核分工**（核心工程）→ 卡顿大头
3. **P2 内存分层 + P1-2 流水线** → 帧率/流畅度翻倍
4. **P3 LCD 120MHz 实测** → 需要真机 + BOD 监控
5. **P4 SIMD** → 压轴

> 里程碑：P0+P1 完成后跑一遍 32fps 动画 + MP3 播放 + 输入法同时开，观感应显著顺滑。

## 风险登记

- **BOD 欠压**：所有频率/背光改动必须沿用 GLM 定案的错峰策略（power.cpp init 半亮 + brownout SEL_1），实测时串口盯 `BOD: Brownout detector` 日志。
- **固件体积**：-O3/LTO 可能撑大 3MB factory 分区，注意 `idf.py size`。
- **IRAM 溢出**：IRAM_ATTR 加多了编译报错，只挑热点。
